# sidebiz/tools 自動処理ツール群

## 目的
各サービスライン(A1/A2/A6...)のうち「Claude(Claude Code)上で自動処理可能な工程」を
ツール化し、案件対応の都度アドホックにプロンプトを書く運用から、再現性のある
入出力契約(prompt-template.md)+ 決定的な前処理・後処理コード(*.mjs)の組み合わせに移行する。

## 設計方針
1. **機械的処理とAI処理を分離する**
   テキスト抽出・正規表現によるコード解析・出力ファイル生成・QAチェックなど
   決定的に処理できる部分は Node.js スクリプトで実装する(再現性・監査可能性のため)。
   意味理解が必要な部分(文語変換・処理内容の要約・リスク評価等)は
   `prompt-template.md` に契約(入出力スキーマ)として定義し、Claudeに実行させる。

2. **実行モードを2系統用意する**
   - **Claude Code モード(既定)**: API키不要。スクリプトが前処理済み入力と契約を
     ファイル出力し、Claude Codeセッション内でClaudeがそれを読んで契約通りの
     出力を生成する。人力検品を経て納品。
   - **APIモード(`--api`)**: `ANTHROPIC_API_KEY` 環境変数が設定されている場合、
     スクリプトがAnthropic Messages APIを直接呼び出し、Claude Code非依存で完結する。
     これは将来ツールを顧客に販売する際、顧客自身のAPIキーで単体稼働させるための
     経路として用意している(下記「販売を見据えた設計」参照)。

3. **後処理QAを必ず入れる**
   契約で定めた必須項目(セクション見出し・必須欄)が出力に含まれているかを
   決定的にチェックする `--validate` 機能を用意する。人力検品の負荷軽減が目的であり、
   人力検品の代替ではない(A1/A2運用手順の実行フローに定める人力検品は省略しない)。

## 販売を見据えた設計(B2フェーズ想定)
- 顧客固有情報・実データを一切ハードコードしない。サンプル入出力はすべて架空データ。
- ライセンス表記・バージョン表記をREADMEに明記し、汎用パッケージとして切り出せる形にする。
- APIモードは顧客が自分のAnthropicアカウント/APIキーで実行する前提とし、
  本パッケージ自体に鍵や課金情報を含めない。
- 実際の販売可否・価格はPhase 4のB2ゲート条件(受託実績確定後の棚卸し)を経てから判断する。
  本ディレクトリの整備はその前提となる実装を先行して用意するものであり、
  販売自体を先行して行うものではない(phase_gates.md準拠)。
