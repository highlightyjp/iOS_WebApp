# A1 議事録整形 出力契約(Claude実行用)

このファイルはツールが自動生成する「前処理済みタスクパッケージ」の雛形。
`format-minutes.mjs` が下記「入力」欄のプレースホルダーを実データで置換したファイルを出力する。
Claude Code セッション内でこのファイルを読み、指示に従って出力すること。

## 役割
あなたは受託業務として、企業の会議ログ(文字起こし後のテキスト)を正式な議事録に
整形する担当者である。改善・要約以上の創作(発言内容の推測・補完)は行わない。
原文に存在しない決定事項やアクションを創作しない。

## 入力
```
やまだ: えーと、じゃあ始めます。今日は新しいかんりしすてむの導入について話したいと思います。

すずき: はい。あのー、まず現状の課題からなんですけど、今のざいこかんりが手作業で
ミスが多いんですよね。月に3件くらい入力ミスが出てます。

やまだ: そうですね、それは前から聞いてます。で、対応策としてはどう考えてますか。

すずき: そうですね、クラウド型のかんりしすてむを導入して、バーコードでの入力に
切り替えるのがいいかなと思ってます。予算は来月中に見積もり取ります。

たなか: なんか、予算感がまだわからないので、そこは一旦保留にしたいです。
決めるのは次回にしましょう。

やまだ: わかりました。じゃあすずきさんが来月中に見積もり取得、たなかさんが
予算枠を上長に確認、ということでお願いします。次回は来月の第一営業日にします。
```

## 変換ルール
1. 口語・言い淀み(えーと、あのー、そうですね等)を整理し、文語・正式表記に変換する
2. ひらがな表記の一般名詞・固有名詞は文脈から漢字表記に変換する(確信が持てない場合は
   原表記を維持し、`【要確認:○○】`と注記する。誤変換より注記を優先する)
3. 発言者名・個人情報は原文のまま保持する(匿名化はNDA同意取得プロセス側で別途処理する。
   本ステップでは匿名化しない)
4. 原文に存在しない情報を補完・推測しない

## 出力スキーマ(厳守・7セクション固定)
以下の見出しをこの順序・この文言で出力すること(QAスクリプトが見出し文字列で検証する)。

```
## 1. 会議概要
（日時・参加者・目的。原文に記載がない項目は「記載なし」と明記する)

## 2. アジェンダ・議題
（原文から抽出。記載がない場合は「記載なし」)

## 3. 決定事項
（箇条書き。原文に決定事項の記述がない場合は「該当なし」)

## 4. 懸案事項
（箇条書き。未解決・保留の論点)

## 5. 次回アクション
（担当者・期限が原文にある場合のみ記載。ない場合は「担当者:未定」「期限:未定」と明記し、
  推測で埋めない)

## 6. 議論詳細・補足
（決定事項/懸案事項に分類しきれない議論の要点)

## 7. 次回開催予定
（原文に記載がある場合のみ。ない場合は「記載なし」)
```

## 出力後の自己チェック(出力の末尾に付記)
- 上記1〜7の見出しをすべて出力したか
- 原文にない情報を補完していないか
- 【要確認:○○】の注記が必要な箇所をすべて拾ったか
