## 目的

公開リポジトリ・公開サイト・共有先に、意図しない秘密情報・個人情報が載ること、およびアプリが利用者データを第三者へ送ること・未固定の外部資源を取り込むことを、公開の前に検出する。対応方針（削除・匿名化・版固定・公開の見送り）の決定は本人が行う。本スキルは検出と列挙、許可リストとの照合、判定材料の提示まで。

## 発動条件

- 公開の前（GitHub Pages 等で公開されるブランチへの反映を含む）
- push の前
- 共有の前（ファイル・リンク・成果物を他者や他サービスへ渡す前）

## 入力

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 公開対象のファイル一式 | 必須 | 公開・push・共有するファイルの全量。リポジトリなら対象コミットの `git ls-files`、共有ならそのファイル群 |
| 許可リスト | 任意（手順4で使う） | 送信・取得を許可する外部ホスト（と版）の一覧。本人が定めるもの。無い場合は手順4を「照合不能（許可リスト未提供）」と記録する。この入力の追加は本セッションによるもので、本人の決定ではない（N4） |
| 公開設定 | 任意 | リポジトリの public/private、Pages の有無と公開URL。無ければ手順1で確認する |

| 根拠の種類 | 区分 | 出典 |
| --- | --- | --- |
| 本人申告 | 発言自体は確認済み・中身は未確認 | 本人の指示（ラウンド3） |
| 実測 | 確認済み（方法・日時を併記） | 本人の指示（ラウンド3） |
| 算出値 | 入力と式が確認済みのときだけ「確認済み（算出）」。未確認の入力が混ざれば「未確認（算出）」 | 本人の指示（ラウンド3） |

本スキル固有の対応付け（本セッションが追加したもので、本人の決定ではない）:

| 対象 | 区分 |
| --- | --- |
| パターン検索の一致（ファイル:行） | 確認済み（実測。コマンド・日時を併記） |

| 外部前提（別リポジトリのワークフロー等）の存在 | 本セッションで取得して確認できたときのみ確認済み。それ以外は未確認 |

## 手順

検出した値そのもの（トークン・金額・氏名等）は、記録・報告・PR 本文・コミットメッセージに転記しない（種別・要約・ファイル:行のみ）。

### 0. 対象の固定

1. 公開対象の一覧と識別子を記録する（リポジトリのルートで実行）。
   ```bash
   C=<公開するコミット>       # 例: HEAD
   git rev-parse "$C"
   git ls-tree -r --name-only "$C" > "$W/files.txt"   # W はリポジトリ外の作業ディレクトリ（mktemp -d）
   wc -l < "$W/files.txt"
   ```
   共有の場合は、渡すファイルの一覧と SHA-256（`sha256sum`）を記録する。
2. push の場合は、公開先にまだ無い差分も記録する。
   ```bash
   git diff --name-only <公開先ブランチ>..."$C"
   ```
   検査は差分だけでなく一式に対して行う（N3）。

### 1. 【B12】公開設定の確認

1. リポジトリの visibility を GitHub の API（`GET /repos/{owner}/{repo}` の `visibility`）または GitHub MCP の取得結果で確認する。
2. 公開URLがある場合は HTTP ステータスを確認する。
   ```bash
   curl -sS -o /dev/null -w '%{http_code}\n' <公開URL>
   ```
3. 方法・日時・結果を記録する。確認できなければ「未確認」と記録する。

### 2. 【B12】秘密情報と個人情報の機械検査

1. 秘密情報・個人情報のパターン検索を、一式（手順0の `files.txt`）に対して行う。検索式は B12 旧下書きの2本を改変せずに使う。
   ```bash
   git grep -nEI "ghp_|github_pat_|sk-ant-|AKIA|Bearer |api[_-]?key|secret|token|password|passcode" "$C" -- . > "$W/secret.txt"
   git grep -nEI "[0-9]{2,4}-[0-9]{2,4}-[0-9]{3,4}|@[A-Za-z0-9.-]+\.[a-z]{2,}|〒|銀行|証券|給与|家賃|年収" "$C" -- . > "$W/pii.txt"
   wc -l "$W/secret.txt" "$W/pii.txt"
   ```
   push の場合は、B12 旧下書きと同じく差分にも実行する（`git diff <公開先ブランチ>..."$C" -U0 | grep -nEi …`）。`-I` によりバイナリ（画像等）は対象外になるため、バイナリのファイル名を「検査範囲外」として記録する。
2. 一致した行ごとに、種別（トークン／APIキー／パスコード／電話番号形式／メール形式／住所／金融機関・金額 等）と、ファイル:行を記録する。値は転記しない。誤検出（変数名・UI 文言に `token` 等が含まれるだけ）と判断したものは、判断の理由を添えて「評価・解釈」として残す（削除しない）。
3. 個人の状況を前提とした記述（氏名・住所・勤務先・家族構成・婚姻歴・健康状態など）を目視で確認する。初期データ・seed・既定値・定数・コメントを重点的に見る。
4. 端末内の秘密情報を列挙する。
   ```bash
   git grep -nEI "(localStorage|sessionStorage)\.setItem|indexedDB\.open|\.put\(" "$C" -- . > "$W/storage.txt"
   ```
   一致箇所から、保存先・種別（パスコード・トークン・APIキー）・平文か否かを読み取る（静的読解のため評価・解釈）。
5. 認証を経ない操作経路（特定入力値での全消去・認証回避・隠し画面）を列挙する。
   ```bash
   git grep -nEI "===?\s*['\"][0-9]{4}['\"]|localStorage\.clear\(\)" "$C" -- . > "$W/bypass.txt"
   ```
   この検索式は本セッションが追加したもの（B12 旧下書きにはコマンドが無い）。一致箇所の分岐先を読み、何が起きるか（全消去・解除・隠し画面）を記録する。
6. 既に公開済みの履歴に残っているかを確認する。手順2-1の一致があるファイルについて、公開先ブランチの履歴で同じ行が既に存在したかを調べる。
   ```bash
   git log --oneline <公開先ブランチ> -G '<一致したパターン（値ではなく検索式）>' -- <ファイル>
   ```
   履歴に残っている秘密情報は「履歴に残存」と記録し、無効化（再発行）が必要という事実を報告する。履歴の書き換えはしない。

### 3. 【B13 の一部】外部依存の棚卸し（版固定と送信先）

1. 外部参照を抽出する。B13 旧下書きの検索式（script src・link href・fetch）と B12 旧下書きの送信経路（`XMLHttpRequest`・`<img src=`・`navigator.sendBeacon`）を使う。
   ```bash
   git grep -noEI '<script[^>]+src="https?://[^"]+"|<link[^>]+href="https?://[^"]+"|fetch\(\s*[`"'"'"']https?://[^`"'"'"']+' "$C" -- . > "$W/ext.txt"
   git grep -nEI 'XMLHttpRequest|navigator\.sendBeacon|<img[^>]+src="https?://' "$C" -- . >> "$W/ext.txt"
   git grep -noEI "@import[^;]*https?://[^'\")]+|url\(\s*['\"]?https?://[^'\")]+|new (WebSocket|EventSource)\(|import\(\s*['\"]https?://" "$C" -- . >> "$W/ext.txt"
   ```
   3行目の検索式（CSS の `@import`・`url()`、WebSocket・EventSource、動的 import）は本セッションが追加したもの（N5）。
2. 文字列連結で組み立てる URL（例: `fetch(base + path)`）は検索式で拾えないため、`fetch(`・`XMLHttpRequest` の全出現を `git grep -nE "fetch\(|XMLHttpRequest"` で数え、手順3-1で URL を特定できなかったものを「宛先未特定」として残す。
3. 1依存1行で、次の列を埋める。

   | 列 | 内容 | 由来 |
   | --- | --- | --- |
   | ファイル:行 | 参照箇所 | B13 |
   | URL / ホスト | 依存先・送信先 | B13 |
   | 種別 | script / style / font / API / 画像 / 中継 / その他 | B13 |
   | 版固定 | 固定（版番号）/ 未固定（例: `.../npm/chart.js` は未固定、`.../remixicon@3.5.0/...` は固定） | B13 |
   | SRI | `integrity` 属性の有無 | B13 |
   | 送信データ | URL・ボディ・ヘッダに利用者データ（`JSON.stringify(data)` 等）が入るか。入る場合は発火条件 | B12 手順3、B13「送信データ」列 |
   | 外部前提 | 別リポジトリのワークフロー・設定への依存（確認済み / 未確認） | B13 |
   | 許可リスト | 手順4の照合結果 | 本セッション追加 |

   B13 の「失敗時挙動」「認証要否」の列、「利用規約上の取得可否」は本スキルでは扱わない（N6）。

### 4. 許可リストとの照合

1. 外部依存の台帳の各行のホスト（と版）を、入力の許可リストと照合する。
2. 結果を「許可リストに記載あり／記載なし／照合不能（許可リスト未提供）」で記録する。記載なしを不許可と言い換えない。
3. 許可リストに版の指定がある場合は、台帳の版と一致するかも記録する。

### 5. 指摘のみ（無断で書き換えない）

1. 検出の表・外部依存の台帳・判定材料（出力）をまとめて本人に報告する。
2. 削除・匿名化・版固定・CDN の差し替え・依存の削除・履歴の書き換え・強制 push は、本人の指示があるまで行わない。
3. 公開の可否は判定しない。判定材料を出すだけにする。

## 注意点

### 守ること（旧下書きの注意点を引き継ぐ）

- 検出した値そのもの（トークン・金額・氏名等）を報告書・PR 本文・コミットメッセージに転記しない。
- 履歴の書き換え・強制 push を独断で行わない。
- 利用者データを含む URL を、確認のために外部サービスへ送信しない。外部依存の確認のために利用者データを外部へ送らない。
- 実データをテスト・サンプルに使わない（架空データのみ）。
- 「個人利用だから問題ない」等の評価を付けない（事実のみ報告する）。
- 指示なく依存の版を上げる・固定する・CDN を差し替える・削除しない。依存先の存在・挙動を推測で「確認済み」と書かない。
- ボット対策の回避・ブラウザ偽装・規約で禁止された自動取得を実装しない。
