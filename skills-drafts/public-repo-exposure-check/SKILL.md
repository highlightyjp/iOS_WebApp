# 公開前の個人情報・秘密情報・外部送信チェック

## 目的
公開リポジトリと公開サイトに、意図しない個人情報・秘密情報が載ること、およびアプリが利用者データを第三者へ送ることを、push 前に検出する。対応方針の決定は利用者が行う。

## 発動条件
- 新規アプリ・新規ファイルの追加
- 初期データ・seed・定数（既定値）の変更
- 外部API・外部画像・外部スクリプトの追加
- main への push 前（GitHub Pages 公開と同時の場合は必須）

## 入力
| 項目 | 内容 |
|---|---|
| 差分 | `git diff --cached` または対象ファイル |
| 公開設定 | リポジトリの public/private、Pages の有無 |

## 出力
| 項目 | 内容 |
|---|---|
| 公開設定 | 確認方法と結果 |
| 検出表 | 種別 / ファイル:行 / 内容の要約（値そのものは書かない） |
| 外部送信表 | 送信先ホスト / 送信される利用者データ / 発火条件 |
| 端末内秘密表 | 保存先（localStorage 等）/ 種別（パスコード・トークン・APIキー）/ 平文か |
| 既公開分 | 既に push 済みで履歴に残っている検出項目 |

## 手順
1. 公開設定を確認する（リポジトリ一覧APIの visibility、公開URLへの HTTP ステータス）。
2. 差分を走査する。
   ```bash
   git diff --cached -U0 | grep -nEi "ghp_|github_pat_|sk-ant-|AKIA|Bearer |api[_-]?key|secret|token|password|passcode"
   git diff --cached -U0 | grep -nE "[0-9]{2,4}-[0-9]{2,4}-[0-9]{3,4}|@[A-Za-z0-9.-]+\.[a-z]{2,}|〒|銀行|証券|給与|家賃|年収"
   ```
   加えて、氏名・住所・勤務先・家族構成・婚姻歴・健康状態など個人の状況を前提とした記述を目視で確認する。
3. 外部送信経路を列挙する。`fetch(` `XMLHttpRequest` `<img src=` `<script src=` `navigator.sendBeacon` の宛先と、URLやボディに利用者データ（`JSON.stringify(data)` 等）が入るかを確認する。
4. 端末内秘密を列挙する。パスコード・トークン・APIキーの保存先と平文か否か。
5. 認証を経ない操作経路（特定入力値での全消去・認証回避・隠し画面）を列挙する。
6. 既に push 済みの検出項目は「履歴に残存」と明記し、秘密情報であれば無効化（再発行）が必要な事実を報告する。
7. 報告する。削除・匿名化・履歴書き換えは利用者の指示後に行う。

## 注意点（やってはいけないこと）
- 検出した値そのもの（トークン・金額・氏名等）を報告書・PR本文・コミットメッセージに転記しない（種別・要約・行番号のみ）。
- 履歴の書き換え・強制 push を独断で行わない。
- 利用者データを含むURLを確認目的で外部サービスへ送信しない。
- 実データをテスト・サンプルに使わない（架空データのみ）。
- 「個人利用だから問題ない」等の評価を付けない（事実のみ報告する）。
