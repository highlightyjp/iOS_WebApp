# 公的オープンデータからの埋め込みデータ生成

## 目的
アプリが扱う実世界データ（駅・路線等）を一次データから再現可能に生成し、仕様（ID規則・スキーマ）への準拠を全件で確認する。サンプルや手書きの擬似データで代替しない。

## 発動条件
- 「全国の駅データ」「国土数値情報から」等、一次データの取込指示
- 埋め込みデータ（`const D=` `const LN=` `MASTER_B64` 等）の新規作成・更新
- 一次データの版更新（例: N02-21 → 新年度版）

## 入力
| 項目 | 内容 |
|---|---|
| 一次データ | 出典URL、データ名・版、取得日、利用規約 |
| 出力スキーマ | 例: `D`（station_id → [lat, name, lng, lines[], LPlines[]]）、`LN`（line_id → …） |
| ID規則 | 例: `station_{romaji}_{lat6}_{lng6}`、`{operator}_{line_romaji}` |
| 要件 | 件数下限、必須検証ケース |

## 出力
| 項目 | 内容 |
|---|---|
| 生成スクリプト | 入出力パスを引数で受ける決定的スクリプト |
| 中間ファイル | JSON（`.gitignore` 対象） |
| 検証レポート | 下表の全項目と数値 |
| 埋め込み結果 | `deterministic-html-patch` 経由の別名出力 |

検証レポート項目:
| 項目 | 基準 |
|---|---|
| 件数 | 要件下限以上（実数を記載） |
| 参照整合 | 駅→路線、路線→駅の孤立参照0件 |
| ID規則準拠 | 全IDを正規表現で検査し、違反件数・違反率・例を記載 |
| 辞書網羅率 | 読み仮名等の補助辞書でカバーできた件数／全件 |
| 必須ケース | 指定ケースの全件結果 |
| 決定性 | 2回生成して出力ハッシュが一致 |

## 手順
1. 出典・版・取得日・規約を記録する。
2. 一次データ（zip・GML・XML等）はコミットしない（`.gitignore` に追加）。
3. 生成スクリプトを決定的にする（入力順に依存しないソート、座標の桁数固定、乱数・現在時刻を使わない）。
4. 生成後、検証レポートの全項目を実行する。ID規則検査の例:
   ```python
   import re
   bad = [k for k in station_ids if not re.fullmatch(r'station_[a-z0-9]+_\d+_\d+', k)]
   print(f'ID規則違反: {len(bad)}/{len(station_ids)}', bad[:5])
   ```
5. 違反・欠損は欠陥として件数付きで報告する。補助辞書の不足は「辞書未収載 n 件」として示す。
6. 2回生成してハッシュ一致を確認する。
7. 埋め込みは `deterministic-html-patch` で別名出力し、構造チェック後に利用者承認を得る。
8. 埋め込まずに利用者がファイルを読み込む方式の場合は、読込時に同じ検証（件数・必須属性の存在）を行う実装になっているか確認する。

## 注意点（やってはいけないこと）
- 主要駅のみの手書き辞書等で「十分」と判断しない。網羅率を数値で示す。
- 件数下限と少数の必須ケースだけで「全件準拠」としない。
- 一次データを間引き・改変しない。統合・除外規則（例: 50m以内かつ同名を統合）は明文化し、件数を記録する。
- 出典不明・擬似（Simulated）データを実データとして埋め込まない。
- 中間ファイル・一次データをリポジトリへコミットしない。
- 凍結物への埋め込みを行わない。
