統合リスト番号と旧番号の対応の根拠: ラウンド2レビューの S8 骨格に「（改変前）…【10】→（改変中）…【22】→（改変後）…【9】」とあり、各段階の内容が B02・B10・B01 の内容と一致することからの推定。統合リスト（ラウンド1）の原文は本リポジトリにも `highlightyjp/app` にも存在せず、未確認（INDEX 11章）。

## 目的

単一HTMLの成果物を改変するときに、次の3つを機械的に検出し、本人が判定するための材料を出す。

1. 改変によって既存の機能・画面要素・保存キー・外部参照が無断で失われること、生成側の「省略」「Stub」による空実装が混入すること（改変前）
2. 置換パッチの空振り（0件）・想定外の多重置換・正規表現の過剰一致（改変中）
3. script の開閉不一致、script 外への JS の漏れ、`</html>` 後の残骸、DOCTYPE の重複、インライン JS の構文エラー（改変後）

対象は構造と機能台帳の差分のみ。機能・表示・ロジックの妥当性、実行時の動作は対象外（動作確認の範囲の棚卸しは S2）。

## 発動条件

- 単一HTMLの成果物を部分修正するとき
- 単一HTMLの成果物を全文差し替えるとき（AI 出力の全文での置き換え、Web UI での全文差し替え、分割出力の貼り合わせを含む）

対象ファイルの例: リポジトリ直下の `*.html`、各アプリディレクトリの `index.html`。

## 入力

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 現行版のHTML | 必須 | リポジトリ相対パスとコミット。`git show <コミット>:<パス>` で取り出せるもの |
| 変更の指示 | 必須 | 本人の指示文。追加・削除・置換の範囲。部分修正では置換表（下記）に落とす |
| 機能台帳 | 必須（なければ生成する） | 関数・DOM id・保存キー・外部URL・`<title>` の一覧。無い場合は手順3で生成する |
| 新版のHTML | 全文差し替えの場合のみ | 差し替え候補の全文（まだ置き換えない） |
| 凍結・封印の情報 | 任意 | 対象が凍結物かどうか（封印台帳）。凍結物には適用しない（S12） |

## 根拠区分

本スキルの出力に付ける根拠区分は「確認済み／評価・解釈／未確認」の3区分のみを使う。

| 根拠の種類 | 区分 | 出典 |
| --- | --- | --- |
| 本人申告 | 発言自体は確認済み・中身は未確認 | 本人の指示（ラウンド3） |
| 実測 | 確認済み（方法・日時を併記） | 本人の指示（ラウンド3） |
| 算出値 | 入力と式が確認済みのときだけ「確認済み（算出）」。未確認の入力が混ざれば「未確認（算出）」 | 本人の指示（ラウンド3） |

本スキル固有の対応付け（本セッションが追加したもので、本人の決定ではない）:

| 対象 | 区分 |
| --- | --- |
| `check-html.mjs` の PASS/FAIL、`inventory_diff.py` の差分行、`patch.py` の件数 | 確認済み（実測。コマンド・実行日時・対象の SHA-256 を併記） |
| PASS/FAIL・OK/NG そのもの | 判定値であり根拠区分ではない。上記の実測結果として記録する |
| 構造検査 PASS から「動作する」と述べること | 評価・解釈。動作は未確認として扱う |
| 削除項目を「指示された削除／指示外の削除」に分けた結果 | 評価・解釈（指示文との照合による判断） |
| 置換表の期待件数 | 本人申告として扱う（宣言自体は確認済み・その件数が正しいかは未確認）。実件数との一致は確認済み（実測） |
| 静的抽出で検出できない項目（動的生成の id・キー、文字列連結の URL、外部 `src` の中身） | 未確認 |

## 手順

流れは B01 構造検査 → B02 再生成回帰ガード → B10 決定版HTMLパッチ の順とする。本スキルでは、B01 を改変前の基線として最初に実行し、改変後にもう一度実行する（この解釈は本セッションによるもの。注意点 N1 で本人確認事項として挙げる）。

### 0. 準備（作業ディレクトリと検査スクリプト）

1. リポジトリの外に作業ディレクトリを作る。検査スクリプトはリポジトリへ追加しない。
   ```bash
   W=$(mktemp -d)
   ```
2. 旧下書きのコードブロックを改変せずに取り出す（リポジトリのルートで実行）。
   ```bash
   cat > "$W/x.py" <<'EOF'
   import sys, re
   t = open(sys.argv[1], encoding='utf-8').read()
   m = re.search(r'^```' + re.escape(sys.argv[2]) + r'\n(.*?)^```', t, re.S | re.M)
   sys.stdout.write(m.group(1))
   EOF
   python3 -I "$W/x.py" skills-drafts/single-html-integrity-check/SKILL.md js      > "$W/check-html.mjs"
   python3 -I "$W/x.py" skills-drafts/regenerated-code-regression-guard/SKILL.md python > "$W/inventory_diff.py"
   python3 -I "$W/x.py" skills-drafts/deterministic-html-patch/SKILL.md python     > "$W/patch.py"
   node --check "$W/check-html.mjs" && python3 -m py_compile "$W/inventory_diff.py" "$W/patch.py"
   ```
   いずれかが失敗したら中止し、失敗した取り出しを報告する。

### 1. 対象の固定

1. 対象のパス・コミット・SHA-256 を記録する。
   ```bash
   P=<リポジトリ相対パス>
   git rev-parse HEAD
   git show HEAD:"$P" > "$W/old.html"
   sha256sum "$W/old.html"
   ```
2. 対象が凍結物（封印台帳に載っている、`<!-- FROZEN -->` 等の表示がある）なら、ここで中止して本人に報告する（S12）。
3. 改変の種別を記録する: 部分修正／全文差し替え。

### 2. 【B01】基線の構造検査（現行版）

```bash
node "$W/check-html.mjs" "$W/old.html" | tee "$W/b01_before.txt"
```

- FAIL の場合は「既存の破損」として項目と行番号を記録する。本スキルでは修正しない（改変後の判定で、既存の破損と改変による破損を区別するために使う）。
- FAIL の項目ごとの行の特定方法は B01 旧下書きの手順3に従う（`leak>0`: script/style 除去後に `const|let|var|function|class|window.|return` で始まる行、`afterHtml>0`: 最後の `</html>` 以降の非空行、`doctype>1`: 2つ目の文書開始位置、`syntax`: ブロック番号・行番号・エラーメッセージ）。

### 3. 【B02】改変前: 機能台帳の抽出、新版との差分、スタブの検出

1. 機能台帳を作る（入力に台帳がない場合）。`inventory_diff.py` の比較相手を空にすると、旧版の全項目が `removed` として出力され、これが台帳になる。
   ```bash
   python3 -I "$W/inventory_diff.py" "$W/old.html" /dev/null > "$W/ledger_before.txt"
   ```
   入力に台帳がある場合も、この出力と突き合わせ、食い違いを記録する。
2. 全文差し替えの場合: 新版を `$W/new.html` に保存し（まだ置き換えない）、差分を取る。
   ```bash
   python3 -I "$W/inventory_diff.py" "$W/old.html" "$W/new.html" | tee "$W/b02_diff.txt"; echo "exit=$?"
   ```
   部分修正の場合: この時点では新版が無いので、差分は手順4の出力に対して手順5で取る。
3. 削除（`-`）の各項目を変更の指示と照合し、「指示された削除」「指示外の削除」に分ける。
4. `[storage_key]` に削除・改名がある場合は S13（保存スキーマ移行）へ渡す。
5. 指示外の削除・`[stub_marker]`・`[empty_function]` が1件でもあれば、差し替えを保留し、台帳差分をそのまま本人に提示する。スタブの補完・削除機能の復元は行わない。
6. 行数の変化（`lines:` 行）は事実として記録する。良否の評価はしない。

### 4. 【B10】改変中: 期待件数の宣言と実件数の照合（部分修正のみ）

全文差し替えの場合は置換パッチを使わないので、この手順は「対象外」と記録して手順6へ進む。

1. 置換表を作業ディレクトリに JSON で作る。各行に期待件数を宣言する（既定 1）。
   ```json
   [{"id": "R01", "old": "<置換前の文字列>", "new": "<置換後の文字列>", "count": 1, "regex": false}]
   ```
   - 先行ルールの `new` が後続ルールの `old` に一致する設計にしない（ドライランは元テキストに対する件数のため）。
   - 入れ子構造（JSON・JS 定数）を置換する場合は、開始・終了のマーカーを `old` に含めて件数 1 を宣言する。
2. ドライランを行う。
   ```bash
   python3 -I "$W/patch.py" "$W/rules.json" "$W/old.html" "$W/out.html" | tee "$W/b10_dryrun.txt"; echo "exit=$?"
   ```
   1行でも `NG`（期待件数と実件数が不一致）があれば、ここで中止し、照合表を本人に報告する。置換表を本人の確認なしに直して再実行しない。
3. 全行 `OK` のときだけ適用する。出力は別名ファイル（`$W/out.html`）に書く。
   ```bash
   python3 -I "$W/patch.py" "$W/rules.json" "$W/old.html" "$W/out.html" --apply | tee "$W/b10_apply.txt"
   ```
   適用時にも件数を照合する（`patch.py` 内の `assert`）。適用前後の SHA-256（`before` / `after` 行）を記録する。
4. 置換の適用後に手作業の修正を混ぜない。混ぜる必要がある場合は本人に報告し、別の改変として扱う。

### 5. 【B02】改変後の台帳差分（部分修正のみ）

```bash
python3 -I "$W/inventory_diff.py" "$W/old.html" "$W/out.html" | tee "$W/b02_diff.txt"; echo "exit=$?"
```

手順3の 3〜6 と同じ扱いをする。置換表で意図した変更以外に台帳の変化があれば、指示外の変化として報告する。

### 6. 【B01】改変後の構造検査

```bash
node "$W/check-html.mjs" "$W/out.html" | tee "$W/b01_after.txt"   # 全文差し替えの場合は "$W/new.html"
```

- 手順2の基線と比べ、各項目を「既存の破損（基線から変化なし）」「改変で生じた破損」「改変で解消した破損」に分ける。
- `<script>` タグの付け外しだけで辻褄を合わせる修正はしない（B01 旧下書きの注意点）。

### 7. 提示と反映

1. 出力（下記）をまとめて本人に提示する。差し替え・反映の可否は本人が決める。
2. 本人の承認後に限り、生成物をリポジトリの対象パスへ反映し、反映後のファイルに対して手順6をもう一度実行して PASS を確認する。
3. 置換表・`patch.py`・結果をコミットに含めるかは本人に確認する（N5）。

## 注意点

### 守ること（旧下書きの注意点を引き継ぐ）

- 検出結果を根拠に、指示なくコードを書き換えない。報告のみ行う。
- スタブ・空関数を自分の判断で補完しない。削除された機能を指示なく復元しない。「省略」等のコメントだけを消して痕跡を隠さない。
- 差し替え・反映の可否を代行判断しない。
- 旧版を上書きしてから差分を取らない（必ず置き換え前に手順3を実行する）。
- ヒット件数を確認しない `replace` / `re.sub` で書き換えない。絶対パスをスクリプトに書かない（引数で受け取る）。
- 凍結物へ直接適用しない。
- 構造検査の PASS を動作の PASS と記載しない。
- 検査スクリプト（`check-html.mjs`・`inventory_diff.py`）をリポジトリへ追加しない（本人の指示がある場合のみ）。
