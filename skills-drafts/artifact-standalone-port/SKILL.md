# claude.ai アーティファクト → 単体アプリ移植

## 目的
claude.ai のランタイム機能に依存するアプリを、本体（アプリロジック）に手を入れずに GitHub Pages / ローカルで動かす。本体との差分を「承認済み改変」として列挙できる状態を保つ。

## 発動条件
- 「claude.ai版をリポジトリへ」「standaloneで動くように」「ローカルで動かす」等の指示
- アーティファクトのHTML/JSX・zip を受け取り、リポジトリに追加する
- 移植済みアプリに同期・中継等の外部連携を追加する

## 入力
| 項目 | 内容 |
|---|---|
| 元アーティファクト | 本体ファイル一式 |
| 承認済み改変リスト | 利用者が許可した本体改変（なければ0件） |
| 配置先 | 例: `coorde/`、`dasgen/` |

## 出力
| 項目 | 内容 |
|---|---|
| ランタイム依存表 | 呼び出し箇所 / 機能 / 代替実装 / 未対応時の挙動 |
| 互換層 | 本体と別の `<script>`（または別モジュール） |
| 承認済み改変一覧 | README 等に列挙（件数と内容） |
| 個人データ除去結果 | 初期データ・seed・定数の確認結果 |
| 外部依存記録 | 別リポジトリのワークフロー・外部API・トークン要否 |

## 手順
1. ランタイム依存の棚卸し。
   ```bash
   grep -noE "claude\.use\(['\"][a-z]+['\"]\)|window\.claude[.\w]*|api\.anthropic\.com|anthropic-version|x-api-key" <本体ファイル>
   ```
2. 依存表を作り、機能ごとに代替を決める（利用者の承認を得る）。
   | 機能 | 代替例（coorde の実装） |
   |---|---|
   | `db` | IndexedDB ＋ `navigator.storage.persist`、失敗時はメモリのみ（保存不可を表示）、旧 localStorage からの初回移行 |
   | `user` | 固定ID |
   | `downloads` | Blob ＋ `<a download>` |
   | `mcp` / `sample` | 未対応は `null` または `code` 付きエラー |
3. 互換層を本体より前の独立ブロックに置き、既に `window.claude.use` が存在する場合は何もしない。
4. 本体の改変は承認済みリストの範囲に限定し、改変箇所と件数を README に列挙する（例: dasgen「移設時の承認済み改変（2件のみ）」）。
5. 個人データ除去: seed・初期データ・定数から実名・実金額・トークン・個人の状況記述を除く（`public-repo-exposure-check` を発動）。
6. 追加連携（GitHub同期・中継等）は互換層側に実装し、本体は無変更とする。トークンはコード・seedに含めず、利用者が端末で入力する方式とする。
7. 外部依存（別リポジトリのワークフロー名、許可ホスト、必要なトークン権限）を記録する。
8. `single-html-integrity-check`、`ios-standalone-webapp-check`、（PWA化する場合）`pwa-service-worker-release` を実行する。

## 注意点（やってはいけないこと）
- 本体ロジック・定数・スキーマ・入出力形式を「ついで」に改変しない。
- 承認済みリスト外の改変を行わない。必要と判断した場合は指摘として報告する。
- APIキー・トークンをコード・seed・コミットに含めない。
- 互換層で保存失敗を握り潰さない（保存不可状態を画面に出す）。
- 動作確認に実データを使わない。
- 別リポジトリ・外部ワークフローへの依存を記録せずに追加しない。
