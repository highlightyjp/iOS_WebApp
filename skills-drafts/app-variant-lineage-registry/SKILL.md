# 派生版・新版の作成と系譜記録

## 目的
同一アプリの版が別ファイルで増える運用において、「どれが最新か」「何が変わったか」「どのファイルから派生したか」「保存データを引き継ぐか」を、作成時点で記録として残す。

## 発動条件
- 「新バージョンとして」「別ファイルで」「vX.Y で」等の指示
- 既存アプリを元に派生アプリを作る
- 凍結物を含むアプリに変更が必要になった（凍結物は上書きせず新版を作る）
- Web UI のアップロード・全文差し替えでファイルを追加・更新した後の記録整理

## 入力
| 項目 | 内容 |
|---|---|
| 親ファイル | 派生元のパス（不明なら「不明」） |
| 作成方式 | 上書き / 新規ファイル（利用者指示） |
| 版番号 | 利用者指定。指定なしなら確認する |
| 変更要約 | 利用者の指示内容 |

## 出力
| 項目 | 内容 |
|---|---|
| 新ファイル | 命名規則に従ったファイル（または上書き） |
| 版表記一致表 | 版番号の記載箇所ごとの値 |
| 台帳行 | `ファイル / 親 / 版 / 作成日(JST) / 保存キー / 状態(現役・凍結・廃止) / 変更要約 / コミット` |
| コミットメッセージ | `<アプリ名> vX.Y.Z: <変更要約>` |

## 手順
1. 作成方式を確定する。指示がなければ確認する。凍結物（`freeze-seal-verify` の対象）は常に新規ファイル。
2. 命名する。既存ファイル名は変更しない。新規は `<app>/index.html`（ディレクトリ型）または `<app>_v<MAJOR>.<MINOR>.<PATCH>.html`（ファイル型）のうち、親と同じ型を使う。
3. 版番号の記載箇所を列挙し、全て同じ値にする。
   - `<title>`
   - アプリ内定数（例: `APP_VERSION`）
   - Service Worker の `VERSION`／キャッシュ名（PWAの場合、`pwa-service-worker-release` を発動）
   - 画面上の版表示
4. 保存キーを決める。親とデータを共有するか分離するかを利用者に確認し、キー変更を伴う場合は `storage-schema-migration` を発動する。
5. 親子関係を記録する。親が不明な場合、類似度等で推定した値は「推定」と明記する。
6. 台帳（利用者が指定したファイル。未指定なら作成可否を確認）に1行追記する。
7. コミットメッセージは内容に即して書く。`〇〇を更新` `Add files via upload` 等の既定文言は使わない。

```bash
# 版表記の一致確認（例: machiapp-techo）
grep -nE "<title>|APP_VERSION|VERSION\s*=" machiapp-techo/index.html machiapp-techo/sw.js
```

## 注意点（やってはいけないこと）
- 既存ファイルのリネーム・削除・統合を指示なく行わない。
- `final` `perfect` `super` `ultimate` `FIXED` 等の序列語を版番号の代用にしない。
- 版番号を飛ばす・重複させる・記載箇所ごとに食い違わせない。
- 親子関係・変更要約を推測で断定しない。
- コミットメッセージに変更内容と無関係な文言を残さない（GitHub の提案文言をそのまま採用しない）。
- 台帳ファイルを指示なく新設しない。
