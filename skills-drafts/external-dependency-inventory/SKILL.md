# 外部CDN・API依存の棚卸し

## 目的
「CDN側の更新で突然壊れる」「API停止で機能が止まる」「別リポジトリのワークフローが無いと動かない」状態を事前に把握し、記録として残す。

## 発動条件
- 外部 `<script src>` / `<link href>` / `fetch` 先の追加・変更
- 長期間更新していないアプリを再利用・再公開する
- オフライン利用・PWA化の要件がある
- 利用者から「急に動かなくなった」と報告を受けた

## 入力
| 項目 | 内容 |
|---|---|
| 対象 | HTMLファイル（複数可）、関連する設定（中継先リポジトリ名等） |

## 出力
依存台帳（1依存1行）:
| 列 | 内容 |
|---|---|
| ファイル:行 | 参照箇所 |
| URL/ホスト | 依存先 |
| 種別 | script / style / font / API / 中継 |
| 版固定 | 固定（版番号）/ 未固定 |
| SRI | `integrity` 属性の有無 |
| 失敗時挙動 | 例: alert のみ / 内部データへフォールバック / 画面停止 |
| 送信データ | 利用者データを含むか（`public-repo-exposure-check` へ連携） |
| 認証要否 | キー・トークンの要否 |
| 外部前提 | 別リポジトリのワークフロー・設定の存在（確認済み / 未確認） |

## 手順
1. 参照を抽出する。
   ```bash
   grep -noE '<script[^>]+src="https?://[^"]+"|<link[^>]+href="https?://[^"]+"|fetch\(\s*[`"'"'"']https?://[^`"'"'"']+' <対象>
   ```
2. 版固定を判定する（例: `.../npm/chart.js` は未固定、`.../remixicon@3.5.0/...` は固定）。
3. 失敗時挙動をコードから確認する（`catch` の内容、フォールバックの有無）。
4. 中継・同期の外部前提（例: 別リポジトリの GitHub Actions ワークフロー）を列挙し、存在を確認できない場合は「未確認」と記載する。
5. 公式APIが無いサイトからの取得が含まれる場合、利用規約上の取得可否を記録する。
6. 台帳を報告する。版の固定・CDN差し替え・依存削除は利用者の指示後に行う。

## 注意点（やってはいけないこと）
- 指示なく依存の版を上げる・固定する・CDNを差し替える・削除しない。
- 依存先の存在・挙動を推測で「確認済み」と書かない。
- ボット対策の回避・ブラウザ偽装・規約で禁止された自動取得を実装しない。
- 外部依存の確認のために利用者データを外部へ送らない。
